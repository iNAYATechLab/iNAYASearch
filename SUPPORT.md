# Support

## Getting Help

If you need help with iNAYASearch, first check the project's documentation and existing GitHub issues.

Before opening a new support request:

1. Read `README.md`.
2. Check `CONTRIBUTING.md`.
3. Search existing issues for similar questions or problems.
4. Check the project roadmap when the question concerns planned functionality.

## Questions and General Help

For general questions about the project, use an appropriate public GitHub discussion or issue when such a channel is available.

When asking a technical question, provide enough context for the problem to be understood.

Useful information may include:

- What you were trying to do.
- What you expected to happen.
- What actually happened.
- Relevant error messages.
- The affected component.
- The relevant version or commit.
- Steps to reproduce the problem.

Do not include passwords, access tokens, private keys, or other sensitive information.

## Bug Reports

If you believe you have found a software defect, use the project's bug report process.

A bug report should be reproducible whenever possible and should include the smallest useful set of information needed to investigate the problem.

For security vulnerabilities, do not use public support channels. Follow `SECURITY.md`.

## Feature Requests

Feature requests should explain:

- The problem or need.
- The proposed capability.
- Why it would be useful.
- Any relevant technical considerations.

Large architectural changes should be discussed before implementation.

## Documentation

If your question is answered by improving the documentation, consider contributing a documentation update.

Documentation improvements are valuable contributions to the project.

## Security Issues

Security vulnerabilities must be reported privately according to `SECURITY.md`.

Do not publish sensitive vulnerability details in public issues or discussions.

## Response Expectations

iNAYASearch is an open-source project, and response times may vary.

A support request does not guarantee an immediate response or implementation.

Please keep support requests focused, respectful, and technically useful.

## Before Asking for Help

When possible, verify:

- The problem still occurs on the current project version.
- The relevant configuration is correct.
- The documented steps were followed.
- The problem is reproducible.
- Existing issues and documentation do not already answer the question.

Providing clear technical information helps reduce investigation time.
